**Status** Source-derived design analysis, v3.5. The requirements below define the v3.5 framework. Independent effectiveness verification remains deployment-specific.

Wave 02 retrieval interfaces; Wave 04 diagnosis; recovery files

The reviewed source inventory is in the [expansion review](../docs/FRAMEWORK-EVIDENCE-EXPANSION.md).

## Placement and alternatives

Discoverability without precise contracts leaves agents guessing which version and evidence apply. Extend existing CLI/manifest ownership. A new interface must preserve schema compatibility and avoid granting decision authority.

The primary owner is **A2.5 Semantic Execution Trace Logging**. Its child clauses preserve this distinct failure mechanism. The competing design is a separate control or deployment profile. Separation is justified when ownership, applicability, enforcement or acceptance cannot be represented by this parent. Absorption requires this explicit detail, a linked acceptance case and a migration record.

## Supporting reported findings

Supporting context for the failure mechanism; this does not establish that the source validates this proposed control or its applicability to every deployment.

### OBS-2026-APR-01 Symbolic Guardrails for Domain-Specific Agents

**Reported facts in the supplied review** A review of 80 agent-security and safety benchmarks found that 85% did not state verifiable requirements. The authors found 74% of evaluated domain requirements could be enforced symbolically, with most requiring simple checks. Released artifacts support reproduction.

**Source-assigned evidence** **E3.** Broad benchmark review, enforceability analysis, empirical evaluation, and public artifacts.

**Limits** Symbolic rules work only where requirements can be represented precisely. They do not solve ambiguous intent, incomplete policy, or unknown future actions.

[Source reference 1](https://arxiv.org/abs/2604.15579)

### OBS-2026-SEP-02 TRACE Runtime Governance, Containment, and Evidence

**Reported facts in the supplied review** TRACE used signed policy bundles, boundary mediation, independent telemetry, deterministic tripwires, graduated containment, and tamper-evident evidence. It rejected all tested tampered chains and reconstructed all tested evidence packages. The authors disclosed that some deposited instruments did not measure their intended outcomes.

**Source-assigned evidence** **E3.** Peer-reviewed, pre-registered elements, substantial adversarial and benign testing, formal state enumeration, and unusually candid instrument audit.

**Limits** Hardware truncation prevented confirmatory side-effect claims, and latency non-inferiority was not established on the main substrate.

[Source reference 1](https://doi.org/10.1109/ACCESS.2026.3733578)

## Requirements and implementation consequences

- **A2.5.R07** Return canonical IDs, source revision, applicability, parent inheritance and evidence status in machine queries.
- **A2.5.R08** Link each requirement to a test or declared verification gap and a supported repair or recovery path.
- **A2.5.R09** Prevent ambiguous aliases and inferred crosswalk chains from producing authoritative compliance answers.
- **A2.5.R10** Bind output to the assessed system and retain explicit unknown, partial, stale and unsupported states.

## Adversarial validation and contrary evidence

Run a synthetic agent workflow that queries a requirement, applies a bounded fix and rechecks the failing test. Test stale editions, ambiguous aliases and a missing enforcement implementation.

Include a legitimate-use control case, denied or unsafe conditions, missing evidence, unavailable dependencies, and the observed recovery outcome where applicable. Measure useful completion and false refusals alongside prevented effects. An existing implementation that demonstrably satisfies the same objective is contrary evidence to adding duplicate machinery. Preserve that result and revise the placement without deleting the underlying failure case.

## Evidence and interpretation

Record actor/origin, entry surface, permitted authority, persistence, affected resource, effect, enforcement point and recovery. Separate disclosed vulnerability, laboratory demonstration, observed exploitation, and incident attribution. Source publication, event and fix dates retain distinct meanings. Deterministic decisions require specified inputs and policy; they do not establish a general safety guarantee.

## Failure and recovery

The deployment owner records partial and unknown outcomes, contains the affected authority where warranted, preserves minimal reconstruction evidence, and revalidates after correction. Quantitative thresholds need declared units, population, uncertainty and policy ownership. Human-state or legal conclusions require their own validation and applicability review.
