# Platform-Specific Agent Security Profiles | C30

**Status** Source-derived design analysis, v3.5. The requirements below define the v3.5 framework. Independent effectiveness verification remains deployment-specific.

## Question and source

Evidence waves 01-06; C30 disposition in docs/FRAMEWORK-EVIDENCE-EXPANSION.md and docs/FRAMEWORK-UPDATE-ISSUES.md

The source record preserves historical proposals, corrections and limitations. Study percentages and analyst scores require the original study denominator and deployment context before use as prevalence or effectiveness claims. The reviewed source inventory is in the [expansion review](../docs/FRAMEWORK-EVIDENCE-EXPANSION.md).

## Placement and alternatives

Existing MCP-19, MCP-18 and related controls offer a home for discovery, audience, identity, catalog changes and fallback. New IDs require an uncovered objective after exact mapping.

The primary owner is **CP.5 Platform-Specific Agent Security Profiles**. Its child clauses preserve this distinct failure mechanism. The competing design is a separate control or deployment profile. Separation is justified when ownership, applicability, enforcement or acceptance cannot be represented by this parent. Absorption requires this explicit detail, a linked acceptance case and a migration record.

## Supporting reported findings

Supporting context for the failure mechanism; this does not establish that the source validates this proposed control or its applicability to every deployment.

### OBS-2026-APR-04 MCP Java SDK DNS Rebinding

**Reported facts in the supplied review** Versions before 1.0.0 did not validate the Origin header. A malicious website could use DNS rebinding to make calls to a local or private-network MCP server as though it were a local agent.

**Source-assigned evidence** **E2.** Reviewed advisory with affected and fixed versions and a specific protocol requirement.

**Limits** Exposure depended on transport and surrounding web-server controls.

[Source reference 1](https://github.com/advisories/GHSA-8jxr-pr72-r468)

### OBS-2026-MAY-05 PraisonAI MCP Path Traversal to RCE

**Reported facts in the supplied review** MCP file tools accepted traversal and absolute paths without containment checks. An attacker could write Python `.pth` files and obtain code execution. Version 4.6.34 patched the issue.

**Source-assigned evidence** **E2.** Reviewed advisory with a concrete path from tool call to arbitrary write and execution.

**Limits** Exploitation depended on access to the MCP call surface and the server user’s filesystem permissions.

[Source reference 1](https://github.com/advisories/GHSA-9mqq-jqxf-grvw)

### OBS-2026-SEP-04 DynamoDB MCP Code Injection

**Reported facts in the supplied review** Crafted table, index, or attribute names in a data-model file could inject code into generated CDK and execute on the deployment host. Versions 2.0.10 through 2.1.5 were affected; 2.1.6 fixed the issue.

**Source-assigned evidence** **E2.** Authoritative coordinated disclosure with affected and fixed versions.

**Limits** The generated application still had to be deployed. No in-the-wild exploitation was reported.

[Source reference 1](https://aws.amazon.com/security/security-bulletins/2026-097-aws/)

### OBS-2026-SEP-05 MCP Atlassian Global-Credential Confused Deputy

**Reported facts in the supplied review** Unauthenticated HTTP MCP requests could reach Jira and Confluence tools that fell back to globally configured operator credentials. A remote caller could act with the operator account’s permissions unless an independent authentication boundary existed.

**Source-assigned evidence** **E2.** Specific request path, identity failure, affected version, and fixed version.

**Limits** Network reachability and server configuration determined practical exposure.

[Source reference 1](https://www.cve.org/CVERecord?id=CVE-2026-77254)

## Requirements and implementation consequences

- **CP.5.R11** Apply the v3.5 MCP child requirements and preserve protocol-independent governance units.
- **CP.5.R12** Validate capability, resource, principal, destination and current-state bindings through the actual deployment paths.

## Adversarial validation and contrary evidence

MCP actor/origin, surface and enforcement. Compare repeated incidents across dates and produce version-bounded conformance evidence.

Include a legitimate-use control case, denied or unsafe conditions, missing evidence, unavailable dependencies, and the observed recovery outcome where applicable. Measure useful completion and false refusals alongside prevented effects. An existing implementation that demonstrably satisfies the same objective is contrary evidence to adding duplicate machinery. Preserve that result and revise the placement without deleting the underlying failure case.

## Evidence and interpretation

Record actor/origin, entry surface, permitted authority, persistence, affected resource, effect, enforcement point and recovery. Separate disclosed vulnerability, laboratory demonstration, observed exploitation, and incident attribution. Source publication, event and fix dates retain distinct meanings. Deterministic decisions require specified inputs and policy; they do not establish a general safety guarantee.

## Failure and recovery

The deployment owner records partial and unknown outcomes, contains the affected authority where warranted, preserves minimal reconstruction evidence, and revalidates after correction. Quantitative thresholds need declared units, population, uncertainty and policy ownership. Human-state or legal conclusions require their own validation and applicability review.
