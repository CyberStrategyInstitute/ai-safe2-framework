# What the evidence model means to each user

## Game developer

Know what changed, which game systems it can affect, which tests ran, what the
reviewers found, and what remains unresolved before merging.

## Engineering lead

Compare the current revision with the previous one, see missing evidence, and
avoid treating a provider outage as approval.

## Security lead

Connect findings to trust boundaries, controls, affected paths, negative tests,
and the human accepting residual risk.

## Product or studio lead

See whether the intended outcome was achieved, what tradeoffs remain, and who
owns the release decision without reading every tool log.

## Auditor or customer reviewer

Inspect a revision-bound record showing what was tested, by which versioned
producer, under which policy, with explicit limitations. The record is
evidence, not automatic certification.

## Everyday Agency Check user

Receive one plain-language Decision Card showing what is supported, what is
unknown, and one next step. The person keeps the final decision.

## Platform and integration developer

Implement one versioned adapter contract rather than coupling the product to
every provider's native output format.
